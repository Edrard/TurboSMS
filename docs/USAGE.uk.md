# TurboSMS: посібник українською

Бібліотека надсилає текстові SMS, повідомлення Viber із текстом/зображеннями та гібридні
повідомлення Viber → SMS через HTTP API TurboSMS. Перемикання на резервне SMS
виконує TurboSMS. Бібліотека передає обидва канали одним запитом, без локального
очікування чи окремого повторного запиту на SMS.

Для отримання статусів від сервісу без постійного опитування дивись
[окремий посібник вебхуків](WEBHOOKS.uk.md): підпис, готовий endpoint,
збереження подій і повторні спроби.

Для підключення логера застосунку дивись [логування PSR-3](LOGGING.uk.md):
Monolog/LoggerInterface, рівні, безпечні поля та поведінка при збої логера.

## Встановлення та налаштування

Потрібні PHP 7.2.5 або новіший, розширення JSON і Hash та залежності Composer.
Сумісність із PHP 7 залишена для наявних програм; для нових інсталяцій обирай
підтримувану версію PHP. Налаштування Composer наведені в [README](../README.md).

У кабінеті TurboSMS увімкни HTTP API та активуй відправників для потрібних
каналів. SMS-альфаім'я та Viber-відправник можуть бути різними. Баланс і дозволи
на країну одержувача перевіряє сервіс.

```php
require __DIR__ . '/vendor/autoload.php'; // Шлях від кореня своєї програми.

use edrard\Turbosms\Api;
use edrard\Turbosms\Message;

$api = new Api([
    'url' => 'https://api.turbosms.ua/',
    'token' => getenv('TURBOSMS_TOKEN'),
]);
```

Налаштуй змінну середовища локально через механізм конфігурації своєї програми.
Не записуй токен у код, Git, URL чи журнали. Відсутній або некоректний токен
викликає `InvalidArgumentException` під час створення `Api`.

## Звичайне SMS: наявні виклики працюють

```php
$message = new Message();
$message->setRecipients(['380000000000'])
    ->setFrom('SMSAlpha')
    ->setText('Ваше замовлення готове.');

$result = $api->sendMessage($message);
```

Режим за замовчуванням — `sms`. Явний `setChannel('sms')` необов'язковий.
Конструктор `new Message($recipients, $from, $text)`, fluent-методи, конструктор
`new Api($config)` та ключі результату `resp` / `error` залишилися сумісними.
Якщо нові параметри не задані, `getConfig()` має попередню структуру.

## Тільки Viber

```php
$message = (new Message(['380000000000'], 'Viber Sender', 'Вітаємо у Viber!'))
    ->setChannel('viber')
    ->setViberTtl(120)
    ->setSequenceId('welcome-customer-42');

$result = $api->sendMessage($message);
```

Цей режим формує лише блок `viber`. SMS не буде створене навіть у разі
недоставки Viber. Якщо не задати `setViberTtl()`, застосовується стандартний
строк Viber у сервісі — 86400 секунд.

## Viber → SMS: чекати Viber, потім дозволити SMS

```php
$message = (new Message(['380000000000'], 'SMSAlpha', 'Замовлення №123 готове.'))
    ->setChannel('hybrid')
    ->setViberFrom('Viber Sender')
    ->setViberText('Замовлення №123 готове. Дякуємо, що обрали нас!')
    ->setViberTtl(60)
    ->setSequenceId('order-123-ready');

$result = $api->sendMessage($message);
```

Тут спільні `from` і `text` використовуються для SMS, а для Viber задані
окремі значення. Якщо Viber відхилить повідомлення раніше, резервне SMS може
бути створене до завершення 60 секунд. Якщо спроби Viber триватимуть до
закінчення строку, SMS залишиться дозволеним після недоставки.
Фактичний час обробки визначає сервіс.

За потреби окремі SMS-параметри можна встановити через `setSmsFrom()` та
`setSmsText()`. Спільні `setFrom()` / `setText()` задають значення за
замовчуванням для кожного активного каналу; конкретні перевизначення мають
пріоритет, навіть якщо спільні значення змінені пізніше.

## Зображення у Viber

Для повідомлення з текстом і зображенням додай `setViberImageUrl()`:

```php
$message = (new Message(['380000000000'], 'Viber Sender', 'Фото вашого замовлення.'))
    ->setChannel('viber')
    ->setViberImageUrl('https://cdn.example.org/orders/123.jpg')
    ->setViberTtl(120)
    ->setSequenceId('order-123-photo');
$result = $api->sendMessage($message);
```

`image_url` передається лише у блоці `viber`. Це має бути абсолютна HTTP(S)-адреса
без логіна/пароля, фрагмента `#...`, пробілів чи керівних символів. HTTPS бажаний.
Параметри запиту та URL без розширення файла дозволені. Не передавай локальний
шлях, `file://` або Base64/data URL. Не-ASCII символи шляху закодуй у форматі URL.

Зображення має бути доступне для TurboSMS без авторизованої сесії твого сайту
та спеціальних HTTP-заголовків. Якщо URL тимчасовий, строк його доступності
має покривати отримання зображення сервісом. Бібліотека не завантажує картинку,
не перевіряє пікселі та не робить окремого HTTP-запиту до URL; доступність,
формат і обмеження медіа перевіряє TurboSMS.

### Гібрид: зображення у Viber, звичайний текст у SMS

```php
$message = (new Message(['380000000000'], 'SMSAlpha', 'Замовлення №123 готове.'))
    ->setChannel('hybrid')
    ->setViberFrom('Viber Sender')
    ->setViberText('Замовлення №123 готове. Додаємо фото.')
    ->setViberImageUrl('https://cdn.example.org/orders/123.jpg')
    ->setViberTtl(60)
    ->setSequenceId('order-123-ready-photo');
$result = $api->sendMessage($message);
```

Резервне SMS використовує свій текст і відправника. URL не додається в текст
SMS автоматично. Таймери мають ті самі значення, що й у текстовому гібридному
повідомленні; зображення не змінює `ttl` або `hybrid_ttl`.

### Зображення за наявним file ID

```php
$message->setViberImageFileId(12345);
```

Метод приймає додатне ціле число — ID зображення, вже завантаженого в TurboSMS.
Рядок `'12345'`, `0`, від'ємні числа та дроби викликають помилку валідації.
Потрібно передати саме зображення свого акаунта: бібліотека не визначає тип
файла за ID й не завантажує новий файл через `file/add`. Це не метод відправлення
документів або локального файла.

Налаштовуй джерело до першого надсилання. Установлення нового ненульового
джерела прибирає попереднє: `setViberImageFileId(12345)` видаляє `image_url`,
а `setViberImageUrl(...)` видаляє `file_id`. Останнє налаштування джерела має
пріоритет; попереднє джерело не відновлюється після скидання.

### Зображення без Viber-тексту

```php
$message = (new Message(['380000000000'], 'Viber Sender'))
    ->setChannel('viber')
    ->setViberImageUrl('https://cdn.example.org/photo.jpg');
$result = $api->sendMessage($message);
```

За наявності зображення точне порожнє значення Viber-тексту `''` прибирає
параметр `text` із запиту. У `hybrid` можна задати `setViberText('')`, але
SMS-текст обов'язково залишити непорожнім. Якщо текст є, для нього залишається
ліміт 1000 символів; наявність зображення цей ліміт не скасовує.

`setViberImageUrl(null)` прибирає лише URL, а `setViberImageFileId(null)` — лише
ID. Після видалення зображення порожній Viber-текст знову некоректний. Перед
переходом до `sms` прибери активне джерело зображення; для звичайних старих
SMS-викликів нічого додавати чи скидати не потрібно.

Помилка медіа може відхилити весь запит до створення повідомлення. Гібридний
режим не гарантує резервне SMS при будь-якій API-помилці: аналізуй виняток і
відповідь сервісу. Не повторюй запит із новим ID автоматично. Зміна URL чи
file ID після вже виконаного запиту не змінює його результат при повторі
того самого `sequence_id`.

Правила параметрів: [офіційна документація TurboSMS](https://turbosms.ua/en/api.html).

## Два різні таймери

| Метод | Що контролює | Значення |
| --- | --- | --- |
| `setViberTtl(60)` | Тривалість спроб доставки у Viber | Ціле число 30–86400 секунд |
| `setHybridTtl(300)` | Граничний вік гібридного повідомлення для створення резервного SMS | Додатне ціле число секунд |

`hybrid_ttl` — загальний строк від створення гібридного повідомлення, а не
додатковий час після Viber. Бібліотека не встановлює його автоматично і не
вигадує верхню межу, якої немає в описі параметра; остаточні обмеження сервісу
перевіряє TurboSMS.

| Намір | Налаштування до виклику `sendMessage()` |
| --- | --- |
| Чекати Viber до 60 с, після недоставки дозволити SMS | `setViberTtl(60)`, без `setHybridTtl()` |
| Чекати Viber до 60 с; після 5 хвилин повідомлення вже неактуальне | `setViberTtl(60)->setHybridTtl(300)` |
| Усе повідомлення актуальне лише 60 с; SMS потрібне лише після ранньої відмови Viber | `setViberTtl(60)->setHybridTtl(60)` |

**Не задавай однакові таймери, якщо хочеш резервне SMS саме після всього
очікування Viber.** Поки спливатиме Viber `ttl`, строк `hybrid_ttl` також
закінчиться, і SMS може вже не створитися.

Таймери — цілі числа: `60` коректно, `'60'`, `60.0`, `true` та `0` некоректні.
Це параметри доставки, вони не є HTTP-тайм-аутами. Для HTTP-запиту надсилання
бібліотека не встановлює загальний тайм-аут; обрив мережі чи процесу все одно
можливий і не доводить, що повідомлення не було прийняте.

## Скидання параметрів і перемикання режиму

`null` у нових необов'язкових налаштуваннях прибирає перевизначення:

```php
$message->setViberTtl(null)   // Стандартний строк Viber у сервісі.
    ->setHybridTtl(null)     // Без явного гібридного дедлайну.
    ->setViberFrom(null)     // Взяти спільний setFrom().
    ->setViberText(null)     // Взяти спільний setText().
    ->setSmsFrom(null)
    ->setSmsText(null);
```

Параметри неактивного каналу викликають помилку валідації замість мовчазного
ігнорування. Перед переходом із `hybrid` на `sms` прибери всі Viber-параметри
та `hybrid_ttl`; перед переходом на `viber` прибери всі SMS-перевизначення.
Для нового логічного повідомлення зазвичай простіше створити новий `Message`.

`getChannels()` повертає готові блоки активних каналів для огляду чи інтеграції.
Цей метод не виконує повну валідацію. `validate()` перевіряє повідомлення без
запиту до мережі; `sendMessage()` викликає валідацію автоматично.

## Результати, часткові помилки та доставка

```php
$result = $api->sendMessage($message);
$response = $result['resp'];
$rejectedRecipients = $result['error'];

foreach ($response['response_result'] as $row) {
    if ($row['response_code'] === 0) {
        $messageId = $row['message_id'];
        // Збережи ID у своїй системі для подальшого зіставлення.
    }
}
```

`resp` містить відповідь TurboSMS. `error` містить відхилені рядки зі
збереженням їхніх індексів. Порожній `error` означає відсутність відхилень
у цій відповіді, а не підтверджену доставку на телефон.

Прийняття гібридного запиту не означає, що SMS уже було відправлене:
воно може взагалі не знадобитися. Для читання поточного стану використовуй
`getMessageStatus()`, описаний нижче, або [обробник вебхуків](WEBHOOKS.uk.md).

## Перевірка статусу доставки

`getMessageStatus(array $messageIds)` приймає непорожній масив ID повідомлень
із відповіді надсилання. Це не номери телефонів і не значення `sequence_id`.
Відхилені під час надсилання рядки з `message_id = null` не можна передавати
на перевірку. Наприклад, ID можна зібрати так:

```php
$messageIds = [];
foreach ($result['resp']['response_result'] as $row) {
    if ($row['response_code'] === 0 && $row['message_id'] !== null) {
        $messageIds[] = $row['message_id'];
    }
}

if ($messageIds !== []) {
    $statusResult = $api->getMessageStatus($messageIds);
    $statusRows = $statusResult['resp']['response_result'];
    $lookupErrors = $statusResult['error'];
}
```

ID перевіряються як рядки форми UUID; бібліотека не нав'язує номер версії UUID.
Масив із пропущеними індексами перетворюється на JSON-список. У документації
методу немає явної межі кількості ID, тому окремий ліміт клієнтом не вигаданий.

Читання стану одного повідомлення:

```php
$statusResult = $api->getMessageStatus(['f83f8868-5e46-c6cf-e4fb-615e5a293754']);

foreach ($statusResult['resp']['response_result'] as $row) {
    if ($row['response_code'] !== 0) {
        continue; // Помилка отримання стану, також є в $statusResult['error'].
    }
    $state = $row['status'];
    $channel = $row['channel'];
    $sentAt = $row['sent'];
    $updatedAt = $row['updated'];
    // Зістав $row['message_id'] зі своєю операцією та збережи отриманий стан.
}
```

| Поле | Як використовувати |
| --- | --- |
| `message_id` | Зіставлення з раніше прийнятим повідомленням |
| `response_code` / `response_status` | Результат отримання інформації про цей ID |
| `status` | Поточний стан доставки |
| `channel` | Фактичний канал, повернутий сервісом; не покладайся на застаріле `type` |
| `sent` | Час надсилання або `null`, якщо повідомлення ще в черзі |
| `updated` | Час останнього оновлення стану |
| `rejected_status` | Причина відмови Viber, якщо повернута; може бути порожнім рядком |
| `click_time` | Додаткова інформація Viber, якщо повернута; може бути `null` |

Код отримання інформації `0` не означає успішну доставку. Наприклад, стан
`Expired` із кодом `0` означає, що перевірка виконана успішно й повідомлення
прострочене. Такий рядок не потрапляє в `error`. Натомість помилка на кшталт
`NOT_ALLOWED_MESSAGE_ID` потрапляє в `error` зі збереженням індексу.

| Стани | Практичне трактування |
| --- | --- |
| `Queued`, `Accepted`, `Sent` | Обробка або очікування результату доставки |
| `Delivered`, `Read` | Доставлено або прочитано |
| `Expired`, `Undelivered`, `Rejected`, `Failed` | Доставка не відбулася; досліди причину та стан у сервісі |
| `Cancelled` | Надсилання скасоване |
| `Unknown` або нове значення | Збережи відповідь і перевір стан згодом; не трактуй як підтвердження доставки |

Для гібридного повідомлення дивись на `channel` у відповіді, не припускай
заздалегідь, що резервне SMS уже створене. Метод повертає один поточний знімок
даних, не запускає автоматичне опитування й нічого не надсилає повторно.
Для відстеження збережи ID та опитуй незавершені операції за розкладом своєї
програми, без безперервного циклу запитів. Часові рядки й додаткові поля
відповіді зберігаються без перетворення часової зони або перейменування.

## Перевірка балансу

```php
$balanceResult = $api->getBalance();
$balance = $balanceResult['resp']['response_result']['balance'];
```

Метод `getBalance()` не має аргументів. Він надсилає порожнє тіло запиту до
`user/balance.json` та повертає звичну структуру:

```php
// Приклад структури, а не результат справжнього звернення до акаунта.
$example = [
    'resp' => [
        'response_code' => 0,
        'response_status' => 'OK',
        'response_result' => ['balance' => 12345.67],
    ],
    'error' => [],
];
```

Число залишається `int` або `float`, отриманим із JSON, без додаткового
округлення чи конвертації валюти. Нуль є коректним результатом; від'ємне
число також не відкидається клієнтом. Якщо поле відсутнє, має неправильний
тип або не є скінченним числом, виникає `InvalidResponseException`.
Некоректна відповідь не перетворюється на нульовий баланс. Окремого поля
валюти в описаній API-відповіді немає, тому бібліотека його не додає.

## Помилки й повтори запитів читання

Статуси та баланс використовують ті самі Bearer-авторизацію, URL із
конфігурації та класи винятків, що й надсилання. Для цих двох методів
установлений загальний HTTP-тайм-аут 30 секунд, переходи за перенаправленнями
вимкнені. Загальна помилка API викликає `ApiException`, мережі —
`TransportException`, структури відповіді — `InvalidResponseException`.

Ці операції не створюють повідомлень, не потребують `sequence_id` і не
виконують автоматичних повторів. Після транспортної помилки запит читання
можна повторити зі своєї програми: це не повторне надсилання. Саме надсилання
зберігає попередні правила тайм-ауту та захисту від дублів.

## Повтори без дублювання

Заздалегідь створи й збережи `sequence_id` разом з операцією у своїй базі.
Використовуй той самий ID та незмінний запит для повтору цієї операції,
зокрема після перезапуску програми. Для нового повідомлення потрібен новий ID.
Один ID охоплює весь гібридний запит, а не кожен канал окремо.

Сервіс зберігає історію ID протягом 30 днів у межах конкретного API-методу.
Бібліотека не створює ID та не робить повторних запитів автоматично.

```php
use edrard\Turbosms\Exception\ApiException;
use edrard\Turbosms\Exception\DuplicateRequestException;
use edrard\Turbosms\Exception\InvalidResponseException;
use edrard\Turbosms\Exception\TransportException;

try {
    $result = $api->sendMessage($message);
} catch (DuplicateRequestException $e) {
    $previousResponse = $e->getResponse();
    // Код 507: зістав попередній результат зі своєю операцією.
    // Не генеруй новий ID лише для обходу цієї відповіді.
} catch (ApiException $e) {
    $apiCode = $e->getCode();
    $apiResponse = $e->getResponse();
    // Оброби відмову API за кодом та структурованими даними.
} catch (TransportException $e) {
    // Результат невідомий. Збережи початковий ID для контрольованого повтору.
} catch (InvalidResponseException $e) {
    // Відповідь некоректна. Надсилання могло відбутися; не повторюй із новим ID.
} catch (\InvalidArgumentException $e) {
    // Локальна помилка параметрів. Запит надсилання не виконувався.
}
```

`DuplicateRequestException` успадковує `ApiException`, тому його потрібно
перехоплювати раніше. Наявний загальний `catch (\Exception $e)` також працює.
У відповіді й повідомленні є персональні дані одержувачів: не записуй їх
безконтрольно в журнали. Транспортні повідомлення винятків не включають токен
чи сирі діагностичні дані запиту.

## Валідація та типові помилки

Перевіряються активні канали: кожен має непорожнього UTF-8 відправника до
25 символів і UTF-8 текст до 1000 символів для Viber або до 1521 для SMS.
Текст обов'язковий, крім Viber-повідомлення зі зображенням. Джерело зображення
перевіряється як HTTP(S) URL або додатний цілий file ID.
Ліміти кодування SMS, зокрема для кирилиці, остаточно перевіряє
сервіс. Номерів має бути 1–5000: міжнародний формат, 7–15 цифр без `+`.

| Ситуація | Що перевірити |
| --- | --- |
| Помилка локальної валідації таймера | Тип `int`, дозволений діапазон, відповідний режим |
| Viber-текст задовгий у `hybrid` | Задай коротший `setViberText()`; SMS-текст може бути іншим |
| Viber не доставився, але SMS немає | Чи вибрано `hybrid`, чи не минув `hybrid_ttl`, результат API та стан у кабінеті |
| Код 507 після повтору | Переглянь `getResponse()` і попередні збережені ID; не надсилай із новим ID автоматично |
| Успішне надсилання, але доставки ще немає | Перевір `getMessageStatus()`, зокрема `status`, а не лише код отримання даних |
| Статус із кодом `0`, але стан `Failed` | Це успішне читання невдалої доставки; рядок не є помилкою отримання інформації |
| Баланс дорівнює нулю | `0` — коректне число; не плутай його з винятком чи некоректною відповіддю |

## Тести та межі підтримки

Із кореня бібліотеки:

```bash
composer install
composer validate --strict
composer check-platform-reqs
composer test
composer audit
```

Якщо це новий checkout бібліотеки без локального `composer.lock`, спочатку
виконай `composer update`. Lock і `vendor/` бібліотеки залишаються поза Git;
застосунок, який її використовує, має вести власний lock.

Тести використовують Guzzle MockHandler, не потребують справжнього токена й не
надсилають повідомлень. Вони перевіряють структуру запитів, таймери, сумісність
SMS, читання статусів і балансу, відповіді та відсутність локальних повторів. Реальне перемикання доставки
виконує зовнішній сервіс; воно не симулюється як підтверджена інтеграційна перевірка.

Підтримуються текстові SMS та Viber із текстом і/або зображенням.
Viber використовує стандартний рекламний
тип API; також підтримуються поточні статуси доставки, баланс і вхідні
звіти доставки `DLR_SMS_API` / `DLR_VIBER_API` через клас `Webhook`.
Кнопки, документи, завантаження файлів, каруселі, опитування, транзакційні шаблони
й обробник вхідних повідомлень/кліків не реалізовані.

Джерело правил сервісу: [офіційна документація TurboSMS](https://turbosms.ua/en/api.html).
